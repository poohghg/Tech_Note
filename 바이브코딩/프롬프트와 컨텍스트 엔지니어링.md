### 프롬프트의 구조
---
> 프롬프트는 AI에게 주는 지시문이다. 좋은 프롬프트는 길이가 긴 문장이 아니라 역할,목표,자료,제약,출력 형식, 검증 기준이 명확한 문장이다.

```
예시.
일반 사용자 대상 교육 자료를 만든다. 하네스 엔지니어링을 자동차 배선 하네스와 사무실 업무 매뉴얼에 비유해 설명하라. 반드시 1) 정의, 2) 왜 필요한가, 3) 구성요소, 4) 실무 예시, 5) 주의점을 포함하라. 전문 용어는 처음 등장할 때 한 문장으로 풀이하라.
```

### 좋은 시스템 지시의 조건
---
> 좋은 시스템 지시는 헌법처럼 짧고 강력해야 한다.
> 세부 업무를 모두 넣으면 오히려 지시가 마거워진다.


#### 좋은 시스템 지시의 조건

| 조건    | 설명                       |
| ----- | ------------------------ |
| 안정성   | 모든 작업에 적용되는 원칙만 담는다      |
| 짧음    | 모델이 매번 기억할 수 있을 정도로 간결하다 |
| 우선순위  | 충돌 시 무엇이 우선인지 분명하다       |
| 금지 범위 | 하면 안 되는 행동을 명확히 한다       |
| 검증 습관 | 완료 전 확인을 요구한다            |

### 컨테스트는 왜 희소 자원인가?
---
> 컨텍스트 창은 AI의 작업 책상이다. 책상 위에 필요한 자료가 없으면 AI는 추측한다. 반대로 책상 위에 모든 자료를 올려놓으면 중요한 문서를 찾기 어려워진다. 
> 
> “먼저 목차를 보고, 필요한 섹션만 읽고, 읽은 섹션명을 답변에 남겨라”가 좋은 컨텍스트 지시다. 

| 구분         | 핵심 질문              | 일상 비유                 |
| ---------- | ------------------ | --------------------- |
| 프롬프트 엔지니어링 | 어떻게 말할 것인가?        | 업무 지시서 쓰기             |
| 컨텍스트 엔지니어링 | 무엇을 보여 줄 것인가?      | 책상 위 자료 정리            |
| 하네스 엔지니어링  | 어떤 환경에서 일하게 할 것인가? | 사무실, 도구, 승인, 검사 체계 만들 |
![[Pasted image 20260730154544.png]]

1. 시스템 지시: 시스템 지시는 모델이 어떤 역할로 행동해야 하는지, 어떤 원칙을 우선해야 하는지 알려주는 기본 규칙이다. 업무 메뉴얼이나 사내 규정에 해당한다. 너무 길면 읽기 어렵고, 너무 짧으면 판단 기준이 부족하다.
2. 사용자 요청: 사용자 요청은 모델이 수행할 작업을 구체적으로 지시하는 프롬프트다. 업무 지시서나 과제 안내문에 해당한다. 너무 길면 읽기 어렵고, 너무 짧으면 판단 기준이 부족하다.
3. 검색과 RGA: 모든 지식을 미리 컨텍스트에 넣는 대신, 필요한 순간에 관련 문서만 찾아오는 검색과 RGA를 활용한다. 검색과 RGA는 모델이 컨텍스트 창을 효율적으로 사용하도록 돕는다. 
4. 장기 메모리: 이전 세션의 배움, 사용자의 선호, 프로젝트의 반복 규칙이 여기에 해당한다. 좋은 메모리는 반복 설명을 줄인다. 하지만 잘못된 메모리가 저장되면 같은 실수를 반복할 수 있으므로 관리 기준이 필요하다.
