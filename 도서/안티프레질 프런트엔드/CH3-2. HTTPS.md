> 웹 서버와 브라우저는 HTTP가 가진 보안상의 취약점을 개선하려고 HTTPS를 사용해 데이터를 주고받도록 한다. HTTPS는 HTTP에 SSL/TLS 프로토콜을 추가하여 데이터를 암호화하고, 서버와 클라이언트 간의 통신을 보호한다. 이를 통해 중간자 공격, 데이터 변조, 도청 등의 보안 위협으로부터 사용자의 데이터를 안전하게 지킬 수 있다.

> HTTPS를 사용하려면 실제로 요청을 보내기 전에 보안 연결을 맺는 과정이 필요하다. 


### HTTP의 문제점

> ==HTTP는 데이터를 암호화하지 않고 평문으로 전송하기 때문에, 데이터가 그대로 노출된상태이다==. 중간자 공격이나 도청 등의 보안 위협에 취약하다. 또한, 데이터 변조가 발생할 수 있으며, 사용자의 개인정보가 유출될 위험이 있다. 이러한 문제점을 해결하기 위해 HTTPS가 등장하였다.

### HTTPS가 데이터를 보호하는 방법

> HTTPS는 HTTP의 보안문제를 해결하기 위해 웹 브라우저와 서버 둘만을 암호화하고 복호화하는 세션 키를 만드는 과정을 거친다. HTTPS에서는 TLS 핸드세이크라는 단계를 먼저 거치게된다. 브라우저와 웹 서버가 서로의 데이터를 암호화, 복호화하는데 사용될 공통된 세션 키를 생성하고 이를 사용하여 서버에 전송할 데이터들을 암호화한 후 요청을 보낸다.

#### 비대칭 키 암호화

![[Pasted image 20260725153955.png|262]]

> HTTPS는 비대칭 키 암호화를 사용하여 브라우저와 서버 간의 안전한 통신을 보장한다. 비대칭 키 암호화는 공개 키와 개인 키라는 두 개의 키를 사용한다. 공개 키는 누구나 접근할 수 있으며, 데이터를 암호화하는 데 사용된다. 반면, 개인 키는 서버만이 가지고 있으며, 암호화된 데이터를 복호화하는 데 사용된다.

#### 대칭 키 암호화

![[Pasted image 20260725154128.png|290]]

> 대칭 키 암호하란 하나의 키로 암호화와 복호화를 모두 수행하는 것이다. TLS 핸드세이크를 통한 보안 연결을 맺고 나면 웹 서버와 브라우저는 동일한 세션 키를 갖는다. 이 세션 키는 대칭 키이므로, 브라우저와 서버는 이 키를 사용하여 데이터를 암호화하고 복호화한다. 대칭 키 암호화를 사용하면 데이터 전송 속도가 빨라지고, 효율적인 통신이 가능하다.

> 대칭 키 암호화는 비대칭 키 암호화보다 속도가 빠르기 때문에, HTTPS에서는 TLS 핸드세이크를 통해 세션 키를 교환한 후, 이후의 데이터 전송에는 대칭 키 암호화를 사용한다. 이를 통해 보안성과 성능을 동시에 확보할 수 있다. 하지만 대칭 키 암호화는 키를 안전하게 교환하는 것이 중요하며, 이를 위해 비대칭 키 암호화를 사용하여 세션 키를 안전하게 전달한다.

### TLS 핸드세이크 과정

> TLS 핸드세이크는 브라우저와 서버가 안전하게 통신하기 위해 세션 키를 교환하는 과정이다. 이 과정은 다음과 같은 단계로 이루어진다.

1. 브라우저가 서버에 연결 요청을 보낸다.
2. 서버는 자신의 공개 키와 인증서를 브라우저에 전달한다.
3. 브라우저는 서버의 인증서를 검증하고, 서버의 공개 키를 사용하여 세션 키를 암호화한 후 서버에 전달한다.
4. 서버는 자신의 개인 키를 사용하여 세션 키를 복호화하고, 이후의 데이터 전송에 사용할 세션 키를 확보한다.
5. 브라우저와 서버는 확보한 세션 키를 사용하여 데이터를 암호화하고 복호화하며 안전하게 통신한다.
