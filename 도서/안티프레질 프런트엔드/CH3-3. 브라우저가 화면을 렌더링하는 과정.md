### 1.HTML 웹 페이지 요청하기

> 웹 서버는 브라우저에 보내듣 HTTP 응답 헤더의 Content-Type필드를 통해 지금 응답하는 데이터가 어떤 타입의 데이터인지 브라우저에게 알려준다.

- Content-Type: text/html 이고 UTF-8로 인코딩된 파일이므로 HTML파일로 다뤄서 DOM파싱을 해야하는 데이터이고, 데이터의 바이트를 UTF-8로 디코딩해야 한다는 것을 브라우저에게 알려준다.
- Content-Encoding: br, gzip, deflate 등으로 압축되어 있는 경우에는 브라우저가 압축을 해제해야 한다는 것을 알려준다.
	- br: Brotli 압축 알고리즘으로 압축되어 있다는 것을 알려준다.
	- gzip: Gzip 압축 알고리즘으로 압축되어 있다는 것을 알려준다.
	- deflate: Deflate 압축 알고리즘으로 압축되어 있다는 것을 알려준다.

> 웹 서버가 응답 헤더를 통해 브라우저에 서버와 현재 전송하는 데이터에 대한 정보를 전달하는 것처럼 브라우저도 요청 헤더를 통해 서버에 브라우저와 현재 전송하는 데이터에 대한 정보를 전달한다.

#### HTML 요청 순서

1. DNS 리졸브와 HTTPS 보안 연결까지 맺어지고 나면 브라우저는 웹 서버에 HTML 파일을 요청한다.
2. 브라우저는 웹 서버에 요청을 보내 때, HTTP 요청 헤더를 사용하여 현재의 요청과 브라우저에 대한 정보를 서버에 보내고, 웹 서버는 HTTP 응답 헤더를 사용하여 전달받은 데이터가 어떤 타입의 데이터인지 브라우저에게 알려준다.
3. 브라우저는 응답 헤더의 Content-Type필드를 확인하여 HTML 파일로 다뤄야 하는지, JSON 파일로 다뤄야 하는지, 이미지 파일로 다뤄야 하는지 등을 확인한다.
4. HTTP헤더는 HTTP 프로토콜을 사용하여 오가는 데이터에 대한 정보와 요청자, 수신자에 대한 정보를 포함한다. 웹 서비스를 효율적으로 개발하도록 돕는 Next.js 등 프레임워크에서도 HTTP 헤더를 사용하여 리소스를 브라우저 맞게 최적화한다.

### 2.HTML 파싱 및 DOM 트리 구축

> 브라우저는 DOM(Document Object Model) 트리를 구축하기 위해 HTML 파일을 파싱한다. 

![[Pasted image 20260726180346.png]]

> DOM은 Document Object Model의 약자로, HTML 문서를 객체 모델로 표현한 것이다. DOM은 HTML 문서의 구조를 트리 형태로 나타내며, 각 HTML 요소는 노드(node)로 표현된다. 이를 통해 브라우저는 HTML 문서를 이해하고, 자바스크립트와 상호작용할 수 있게 된다.

> HTML이 웹 페이지가 어떻게 구조화되는지를 정적으로 표현한다면 DOM은 브라우저에서 이 HTML파일을 해석해서 화면에 렌더링하려고 사용하는 동적인 객체 모델이다. 즉, HTML은 정적인 문서이고 DOM은 동적인 객체 모델이다.

> 브라우저는 웹 서버에서 받은 HTML 스트링을 문법 규칙에 맞게 파싱한 후 div,body 등의 요소를 노드라는 이름의 객체로 만들어 메모리에 저장한다.
> 
> 각 노드에는 div,span 처럼 HTML 요소를 식별하는 tagName과 스타일 정보를 비롯한 속성 정보를 저장하는 attributes, 자식 노드와 부모 노드의 관계를 나타내는 childNodes, parentNode 등의 속성이 존재한다. 이러한 노드들을 연결하여 트리 구조로 만들어진 것이 바로 DOM 트리이다. 이 전체 트리는 메모리에 저장되어 스크립트를 통해 DOM API의 형태로 접근된다. 


> HTML 파싱 중 script 태그를 만나면 브라우저는 HTML 파싱을 일시 중단하고, 스크립트 파일을 다운로드하고 실행한 후 다시 HTML 파싱을 이어간다. 이는 스크립트가 DOM에 접근하여 조작할 수 있기 때문이다. 따라서 스크립트가 DOM을 조작하기 전에 DOM이 완전히 구축되도록 하기 위해, 일반적으로 script 태그는 body 태그의 마지막에 위치시키거나, defer 또는 async 속성을 사용하여 비동기적으로 로드하는 것이 권장된다.

#### DOMContentLoaded 이벤트 와 load 이벤트

> 브라우저는 HTML 파싱을 마치고 ==DOM트리를 구축하고 나면 DOMContentLoaded 이벤트==를 발생시킨다. 이 이벤트는 HTML 문서가 완전히 로드되고 DOM 트리가 구축되었음을 나타낸다. 따라서 이 이벤트를 통해 자바스크립트는 DOM 요소에 접근하고 조작할 수 있다.

> Load 이벤트는 ==DOM트리 구축뿐 아니라 이 DOM트리가 화면에 각각의 노드들이 참조하는 여러 외부 리소스(이미지, 스타일시트, 스크립트 등)==까지 모두 로드되었을 때 발생한다. 따라서 load 이벤트는 DOMContentLoaded 이벤트보다 늦게 발생하며, 모든 리소스가 준비된 후에 실행되어야 하는 코드에 적합하다.

#### HTML 파싱 요약

1. 브라우저는 HTML 파일을 파싱해서 DOM이라는 객체 모델을 구축한다.
2. HTML은 웹 페이지의 정적 표현이고, DOM은 웹 페이지를 동적으로 변경하게 해주는 객체 모델이다.
3. 브라우저는 HTML 각 요소를 노드라는 형태의 객체로 메모리에 저장한다. 이 노드에는 문서 노드, 요소 노드, 텍스트 노드, 속성 노드 등 다양한 종류가 존재하며, tagName, attributes, childNodes, parentNode 등의 속성을 가진다.
4. HTML을 파싱하는 HTML파서는 다른 프로그래밍 언어의 파서와는 다르게 문맥 에 따라 유연하게 파싱한다. 예를 들어, HTML 문서에서 닫는 태그가 생략된 경우에도 HTML파서는 이를 보완하여 DOM트리를 구축한다.
5. HTML 파싱이 마무리되어 DOM트리가 구축되면 브라우저는 DOMContentLoaded 이벤트를 발생시킨다. 이 이벤트는 HTML 문서가 완전히 로드되고 DOM 트리가 구축되었음을 나타낸다.

### 3. CSS 파싱 및 CSSOM 트리 구축

> DOM은 HTML문서의 각요소가 가진 계층 구조를 표현하는 모델로, 각 요소가 어떤 크기와 어떤 색깔로, 어디에 그려야 할지 등의 스타일 정보를 알지 못한다. 따라서 브라우저는 CSS 파일을 파싱하여 CSSOM(CSS Object Model)이라는 객체 모델을 구축한다.

> CSSOM 트리는 각 요소에 적용될 스타일이 어떤 구조로 이루어지는지를 나타낸다. 브라우저는 DOM 트리와 CSSOM 트리를 결합하여 렌더 트리를 구축한다. 렌더 트리는 각 요소가 화면에 어떻게 표시될지를 결정하는데 필요한 정보를 포함하고 있다.
