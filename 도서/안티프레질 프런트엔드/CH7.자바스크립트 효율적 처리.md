> 자바스크립트의 과도한 연산으 한 프레임에 주언지 16ms의 시간을 초과하면 프레임 드랍을 발생시킨다. 브라우저는 하나의 메인 콜 스택에서 렌더링과 관련된 대부분의 작업을 처리하므로 자바스크립트가 메인 콜 스택에 실행되는 동안에는 다른 작업을 할 수가 없다. 따라서 하나의 프레임에서 처리되는 자바스크립트의 양을 적절하게 조절하는 방법이 필요하다.

![[Pasted image 20260804152958.png|506]]

- 메인 스레드에서 실행되는 연산들을 적절히 나누어 효율적으로 실행하는 겨우
	- setTimeout, setInterval, requestAnimationFrame, requestIdleCallback 등을 활용하여 연산을 나누어 실행
- 무거운 연산을 별도의 스레드에서 실행하게 한 후 결과를 메인 스레드로 넘겨주는 경우 
	- 서비스 워커(Service Worker), 웹 워커(Web Worker)를 활용할 수 있다.

#### requestAnimationFrame

> window.requestAnimationFrame() 메서드는 브라우저에게 애니메이션을 업데이트할 준비가 되었음을 알려주는 메서드이다. ==다음 리페인트 바로 전에 브라우저가 애니메이션을 업데이트할 지정된 함수를 호출하도록 요청==한다.

![[Pasted image 20260804153348.png|477]]

```javascript
function animate() {
  // 애니메이션 로직 수행
  // ...

  // 다음 프레임에 animate 함수를 호출
  requestAnimationFrame(animate);
}

```

> 브라우저는 다음 리페인트를 수행하기 전에 rAF에 등록된 콜백 함수를 실행한다. 메인 스레드에서 현재 실행되는 프레임 작업을 방해하지 않아 rFA를 사용하면 메인 스레드의 작업을 방해하지 않고 간단한 애니메이션 등 UI 작업을 효율적으로 처리한다.

- 리페인트 직접에 rAF에 등록한 콜백 함수의 호출을 보장한다.
	- 스크립트 실행 시점을 브라우저가 제어하므로, 브라우저의 리페인트 주기와 동기화되어 애니메이션이 부드럽게 실행된다.
- 다만 해당 콜백 후에 리페인트가 일어나기에 애니메이션이 끝난 후에 DOM 변경이 일어나면, 다음 리페인트까지 기다려야 하므로, DOM 변경이 바로 적용되지 않는다.
	- 간단한 애니메이션 작업을 적용해야한다.

> 즉, rAF는 애니메이션 처리 등 가벼운 스크립트를 브==라우저가 화면을 갱신하는 사이클에 맞추어 콜백으로 수행해== 프레임과 프레임 사이 메인 스레드에서 동작하는 여러 자바스크립트의 실행을 방해하지 않아 웹 페이지의 성능을 높여 준다.


#### requestIdleCallback

> window.requestIdleCallback() 메서드는 브라우저의 idle 상태에 호출될 함수를 대기열에 넣는다. 이를 통해 개발자는 애니메이션 및 입력 응답 등 대기 시간이 중요한 이벤트에 영향을 미치지 않고 메인 이벤트 루프에서 백그라운드 및 우선순위가 낮은 작업을 수행한다. 함수는 FIFO(First In First Out) 방식으로 호출되며, 브라우저가 idle 상태일 때 실행된다.

![[Pasted image 20260806171242.png|593]]


```javascript
function myNonCriticalFunction(deadline) {
  while ((deadline.timeRemaining() > 0 || deadline.didTimeout) && tasks.length > 0) {
    const task = tasks.shift();
    task();
  }
}
```

> rIC는 브라우저가 유휴 상태일 때, 즉 중요한 렌더링 작업이나 사용자 입력 처리가 없어 메인 스레드의 콜 스택이 비었을때 스케줄된 콜백을 실행한다. rIC는 로깅이나 데이터 전송과 같이 우선순위가 낮은 작업을 수행하는 데 적합하다. rIC는 브라우저의 유휴 상태를 감지하여 콜백을 실행하므로, 메인 스레드에서 중요한 작업이 진행 중일 때는 콜백이 지연될 수 있다.

#### workers

> 웹 워커(Web Worker)는 브라우저에서 자바스크립트를 별도의 스레드에서 실행할 수 있는 기능을 제공한다. 이를 통해 메인 스레드에서 실행되는 자바스크립트의 부하를 줄이고, UI 응답성을 향상시킬 수 있다. 웹 워커는 메인 스레드와는 독립적으로 실행되며, 메시지를 통해 데이터를 주고받을 수 있다.

- 복잡한 데이터 처리 및 계산: 웹 워커를 사용하면 복잡한 계산이나 데이터 처리를 메인 스레드와 분리하여 수행할 수 있다. 이를 통해 UI가 멈추거나 느려지는 문제를 방지할 수 있다.
- 파일 및 데이터베이스 조작: 웹 워커를 사용하면 파일 읽기/쓰기, 데이터베이스 쿼리 등과 같은 작업을 메인 스레드와 분리하여 수행할 수 있다. 이를 통해 UI가 멈추지 않고 사용자 경험을 향상시킬 수 있다.
- 실시간 데이터 처리: 웹 소켓을 통한 시실간 데이터 처리나 비디오 및 오디오 처리 등 실시간 스트리밍 작업 을 웹 워커를 사용하여 메인 스레드와 분리하여 수행할 수 있다. 이를 통해 UI가 멈추지 않고 실시간 데이터를 처리할 수 있다.
- 암호화 작업: 클라이언트 사이드에서 수행되는 암호화 및 해시 계산 등 보안 관련 작업
- 시물레이션 및 게임 로직: 복잡한 물리 계산이나 게임의 로직 처리

> 웹 워커와 웹 워커의 일종인 서비스 워커는 브라우저에서 무거운 연산을 메인 스레드가 아닌 별도의 백그라운드 스레드에서 실행하게 돕는다. 이를 통해 메인 스레드는 UI와 인터렉션 처리에 집중하며 이는 웹 페이지의 반응성을 크게 향상시킨다. 다만 워커는 사용은 웹 페이지의 복잡성을 증
